4. Screen-by-screen question spec
Step 1 — Fixed assets (fixedAssets)
Repeating card, one per asset, with an "+ Add another asset" button and a Remove button per card. Each asset card collects:
Date first used (date input)
Cost of asset (number input)
Describe the asset (free text)
Asset category (single-select pill grid) — options exactly: Building Industrial, Building Non-Industrial, Plants (excluding Furniture & Fittings), Agricultural Plants Expenditure, Furniture & Fittings Expenditure, Public Transport Motor Vehicles, Motor Vehicles Expenditure, Plantation Equipment, Construction Plants Expenditure, Research & Development Expenditure, Housing Estate Expenditure, Land, Ranching & Plantation, Software, Others
Each category has a fixed salvage % and useful life (years) used for the capital allowance calculation (see Section 6.1 table). Below the category grid, a live calc line shows: default salvage %, computed salvage value, useful life, and annual depreciation charge. Land shows "no salvage % or useful life applies (N/A)" instead of a calculation.
Step 2 — MNE / CFC check (mneCfc)
Two independent Yes/No questions (answering one does not hide/reset the other):
"Are you part of a Multinational Enterprise (MNE) Group?"
"Is any of your constituent entities a Controlled Foreign Company (CFC)?"
If either is "Yes", do not let the user continue the self-filing flow. Redirect them into a separate "talk to a tax professional" contact flow instead — this filing path does not support MNE/CFC cases. Requirements for this handoff:
The redirect should happen as soon as either answer is "Yes" (don't wait for both questions to be answered).
The prototype's inline terminal message ("This filing path doesn't cover CFC cases — please consult a tax professional") can be shown briefly/as a transition state, but the user should then land on a dedicated contact/handoff screen — not remain on the wizard with a Continue button still available.
Open item for product/design: what does the "talk to a tax pro" flow actually consist of (a contact form, a booking link, an in-app referral to a human advisor, a phone number)? This needs a decision before engineering can build the destination screen — see Section 7, item 4.

5. Reusable interaction patterns (must be built as components, reused across steps)
5.1 Chip-select-then-amount
Used in Cost of Sales, SFP gated sections, Trade Payables/Equity, Add-backs, Deductions, and Admin Expense.
Renders a grid of chip buttons, one per option, prefixed +.
Tapping a chip toggles it to a "selected" state (prefixed ✓) and reveals an amount input for it in a panel below.
Amount panel groups all currently-selected items with individually labeled currency inputs.
Un-tapping a chip removes it from the amount panel and clears its stored value.
A running subtotal for the section should be visible (the prototype relies on the sidebar ledger for totals — decide with design whether each section also needs its own subtotal line).
5.2 Radio pill (single select)
Used for Yes/No questions and single-choice grids (asset category, sector). Selected state gets a solid fill; unselected is outlined.
5.3 Gate block
A section that stays collapsed/inactive until a preceding Yes/No (or its own toggle) opens it, at which point its fields become interactive. Used in SFP and Profit Adjustment.
5.4 Repeating card (asset entry)
"+ Add another asset" appends a new blank card; each card has its own Remove control and independent field state, and the depreciation calc line updates live per-card without losing input focus (this matters: recomputing the whole step on every keystroke breaks focus — recalculate just the affected card/line, not the full render tree).
5.5 Live ledger sidebar
Sticky panel, visible on every step, showing running totals for: Revenue, Direct cost, Gross profit, Admin expenses, Add-backs, Deductions, and Capital allowance (sum of all asset depreciation). If MNE or CFC was answered "Yes", show a flag: "CFC / MNE flagged — flow would stop and route to a tax professional here." Collapses above the main content on narrow/mobile viewports.

6.2 Profit & Loss (fully computed, in this order)
direct_cost   = opening_inventory + purchases + other_direct_cost + factory_overheads − closing_inventory
gross_profit  = revenue − direct_cost
operating_income = gross_profit − admin_expenses_total
finance_cost  = 0   // intentionally out of scope for this build — no input collected, confirmed with product
opbt          = operating_income − finance_cost   // Operating Profit Before Tax
taxable_profit = opbt + addbacks_total − deductions_total
taxation      = max(taxable_profit, 0) × [CIT_RATE]   // ⚠️ rate intentionally left blank — see Section 7, item 2
profit_after_tax = opbt − taxation
oci           = 0  // Other Comprehensive Income — intentionally out of scope for this build, confirmed with product
profit_for_year = profit_after_tax + oci
Display rows, in order: Revenue, Direct Cost, Gross Profit, Administrative expenses, Operating Income, Finance Cost, Operating Profit Before Tax, Taxation, Profit After Tax, Other Comprehensive Income, Profit For The Year.
6.3 Live ledger sidebar figures
Same direct_cost / gross_profit formulas as above, plus running sums of admin expenses, add-backs, and deductions, plus total capital allowance from 6.1.
